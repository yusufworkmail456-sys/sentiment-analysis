Sentimetter / Documentation

Documentation

Analisis sentimen multi-platform dengan IndoBERT, dashboard real-time, dan insight bertenaga AI — self-hosted dan open source.

Introduction

Sentimetter adalah platform analisis sentimen self-hosted yang melakukan scraping opini publik dari 6 platform social media, mengklasifikasikan dengan model transformer IndoBERT, mengkategorikan per topik domain, dan menampilkan hasil melalui dashboard interaktif dengan executive summary yang di-generate AI.

Dibangun dengan Streamlit, Plotly, HuggingFace Transformers, dan LLM API kompatibel OpenAI. Dirancang untuk self-service: tidak perlu interaksi terminal — semuanya berjalan dari web UI.

Open Source · Lisensi MIT Bebas digunakan, dimodifikasi, dan di-deploy. Generic — bisa untuk domain, brand, atau topik apa saja.

Mekanisme Scraping & Sentiment

Memahami cara Sentimetter mengumpulkan data dan mengklasifikasikan sentimen.

Cara Kerja Scraping

Setiap platform punya API dan struktur data berbeda. Sentimetter menggunakan library khusus per platform untuk mengambil komentar, review, atau artikel. Data yang diambil: source, text, author, date, likes, url.

Data tidak acak — tiap platform menggunakan urutan defaultnya sendiri:

PlatformLibrarySort OrderAuthTime Filter?
Instagraminstagrapi + web APITop posts dulu, recent fallbackSession ID❌ Tidak
YouTubeyoutube-comment-downloaderSORT_BY_RECENT (terbaru dulu)Tidak perlu❌ Tidak
Web NewsBing News RSS + trafilaturaRelevansi + recency BingTidak perlu❌ Tidak
Play Storegoogle-play-scraperSort.NEWEST (review terbaru)Tidak perlu❌ Tidak
Facebookfacebook-scraperRecent postsSession cookie❌ Tidak
TikTokTikTokApi + PlaywrightRecent videosms_token❌ Tidak
Tidak ada time range filter di scraper API platform tidak mendukung filter tanggal saat scraping. Urutan ditentukan oleh algoritma platform (populer, terbaru, atau relevansi). Hasil adalah snapshot dari apa yang platform anggap paling relevan saat itu.

Alur Scraping per Platform

Instagram

flow
1. Login via session_id (web API)
   └─ Ambil sessionid cookie dari browser
   └─ Fallback: instagrapi (username + password)
2. Search hashtag: #{keyword}
3. Get posts from hashtag + timeline feed
   └─ Filter posts with comments > 0
4. For each post (max 15 posts):
   └─ Get comments (max 50 per post)
   └─ Extract: text, author, date (UTC), likes, post URL
5. Sleep between posts (rate limit protection)

YouTube

flow
1. Search: ytsearch8:{keyword} via yt_dlp
   └─ fallback: via WARP proxy if direct fails
2. Get top 8 videos
3. For each video:
   └─ Get comments sorted by SORT_BY_RECENT (newest first)
   └─ Extract: text, author, date (timestamp), votes, video URL
4. Stop when max_comments reached

Web News

flow
1. Query Bing News RSS: https://www.bing.com/news/search?q={keyword}
   └─ fallback: via WARP proxy
2. Parse RSS feed (feedparser)
3. For each article (max 3x target):
   └─ Resolve Bing redirect → actual article URL
   └─ Fetch HTML
   └─ Extract text via trafilatura
   └─ Skip if text < 200 chars
   └─ Extract: text (max 3000 chars), source, date, URL

Play Store

flow
1. Match keyword to configured app IDs (PLAYSTORE_APPS)
   └─ If no match: search Play Store for keyword
2. For each app:
   └─ Get reviews sorted by Sort.NEWEST
   └─ If keyword is not a known app: filter reviews by keyword
   └─ Extract: text, author, date, thumbsUpCount, app URL
3. Distribute max_comments across apps evenly

Cara Kerja Sentiment Analysis

Setelah scraping, semua teks diklasifikasikan menggunakan model HuggingFace Transformers. Default: w11wo/indonesian-roberta-base-sentiment-classifier (IndoBERT).

sentiment pipeline
┌──────────────────────────────────────────────────────────┐
│                  Klasifikasi Sentiment                  │
│                                                            │
│  Input:  scraped text (max 128 tokens, truncated)          │
│  Model:  IndoBERT (Indonesian RoBERTa)                     │
│  Output: label + confidence score                          │
│                                                            │
│  ┌──────────────────────────────────────────────────────┐ │
│  │  Batch processing (16 texts per batch)                │ │
│  │                                                       │ │
│  │  text → tokenizer → RoBERTa → softmax → label+score  │ │
│  │                                                       │ │
│  │  Labels:  positive → "Positif"                         │ │
│  │           neutral  → "Netral"                          │ │
│  │           negative → "Negatif"                         │ │
│  │                                                       │ │
│  │  Score: 0.0 - 1.0 (confidence)                        │ │
│  │  ≥0.6  → "yakin" (confident)                          │ │
│  │  <0.6  → "ragu"  (uncertain, flagged)                 │ │
│  └──────────────────────────────────────────────────────┘ │
│                                                            │
│  Post-processing:                                          │
│  └── classify_df() → categorize into domain topics        │
│      (Pelayanan, Klaim, Sistem Digital, etc.)             │
└──────────────────────────────────────────────────────────┘
Model Accuracy IndoBERT mencapai akurasi ~85% untuk sentimen Bahasa Indonesia. Prediksi low-confidence (< 0.6) are flagged as "ragu" and may need manual review. For other languages, change SENTIMENT_MODEL di .env.

Kategorisasi Domain

Setelah sentiment classification, teks dikategorikan ke topik domain menggunakan keyword matching di categorize.py. Kategori dapat dikustomisasi sesuai domain.

categorize.py
CATEGORIES = {
    "Pelayanan":      ["layanan", "cs", "antri", "ramah", "kasar", ...],
    "Klaim":          ["klaim", "pencairan", "ditolak", "berkas", ...],
    "Sistem Digital": ["aplikasi", "login", "error", "bug", "down", ...],
    "Produk":         ["produk", "jht", "manfaat", "premi", ...],
    "Penipuan":       ["penipuan", "scam", "hoax", "palsu", ...],
    # Edit CATEGORIES dict to match your domain
}

GSS (Global Sentiment Score)

Skor sentimen keseluruhan dalam skala 0-100:

formula
GSS = (Positif + 0.5 × Netral) / Total × 100

Range:
  0-40  → 🔴 Kritis (mayoritas negatif)
  40-60 → 🟡 Netral
  60-80 → 🟢 Baik
  80-100→ 🟢 Sangat Baik

Deduplikasi Data

Setelah semua source terkumpul, data di-dedupe berdasarkan (source, text[:200].lower()) — komentar yang sama dari platform yang sama dihilangkan.

Skor Sentiment (−100 s/d +100)

Selain GSS, terdapat Skor Sentiment dalam rentang −100 s/d +100:

formula
Skor = %Positif − %Negatif

Contoh: 20% positif, 69% negatif → Skor = 20 − 69 = −49

Keyakinan Prediksi (Confidence Score)

Setiap komentar memiliki confidence score (0.0–1.0) dari model. Threshold:

≥ 0.6"yakin" — prediksi confidence tinggi
< 0.6"ragu" — prediksi mungkin meleset, diberi badge ⚠️

Deployment

Panduan step-by-step deploy Sentimetter di server Linux.

1

Clone repository

bash
git clone https://github.com/yusufworkmail456-sys/sentiment-analysis.git
cd sentiment-analysis
2

Buat virtualenv & install dependencies

bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt

# CPU-only server? Install torch first to skip CUDA:
# pip install torch --index-url https://download.pytorch.org/whl/cpu
3

Install Playwright (untuk scraper TikTok)

bash
playwright install chromium
4

Download font

bash
mkdir -p assets/fonts
# On Debian/Ubuntu:
cp /usr/share/fonts/truetype/dejavu/DejaVuSans.ttf assets/fonts/
cp /usr/share/fonts/truetype/dejavu/DejaVuSans-Bold.ttf assets/fonts/
5

Konfigurasi environment

bash
cp .env.example .env
nano .env

Set LLM endpoint — provider apa pun yang kompatibel OpenAI (OpenAI, Ollama, vLLM, LiteLLM, router pilihan Anda, dll). Yang dibutuhkan hanyalah base URL + API key:

.env
# Contoh 1 — OpenAI
LLM_BASE_URL=https://api.openai.com/v1
LLM_MODEL=gpt-4o-mini
LLM_API_KEY=sk-...

# Contoh 2 — Ollama lokal (tanpa API key)
LLM_BASE_URL=http://localhost:11434/v1
LLM_MODEL=llama3.1
LLM_API_KEY=

# Contoh 3 — provider/router lain
LLM_BASE_URL=https://provider-anda.com/v1
LLM_MODEL=nama-model-anda
LLM_API_KEY=key-anda

Lihat Configuration untuk semua opsi.

6

Buat systemd service

/etc/systemd/system/sentiment.service
[Unit]
Description=Sentimetter
After=network.target

[Service]
Type=simple
User=root
WorkingDirectory=/opt/sentiment-analysis
Environment=HF_HOME=/opt/sentiment-analysis/hf
ExecStart=/opt/sentiment-analysis/venv/bin/streamlit run app.py \
    --server.port 9120 \
    --server.address 127.0.0.1 \
    --server.headless true
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
7

Enable & start service

bash
systemctl daemon-reload
systemctl enable --now sentiment-analysis
systemctl status sentiment
8

Verifikasi

bash
systemctl is-active sentiment-analysis
curl http://localhost:9120
journalctl -u sentiment -f

Akses Web

Sentimetter dapat diakses dengan dua cara — pilih sesuai kebutuhan.

Opsi A — IP Publik (simplest)

Jalankan Streamlit langsung di 0.0.0.0 agar dapat diakses dari IP publik. Tidak butuh domain atau Nginx.

systemd
ExecStart=/opt/sentiment-analysis/venv/bin/streamlit run app.py \
    --server.port 9120 \
    --server.address 0.0.0.0 \
    --server.headless true

Akses di http://SERVER_IP:9120. Buka port di firewall jika perlu:

bash
ufw allow 9120/tcp
Tanpa HTTPS Opsi ini tidak menggunakan HTTPS. Akses langsung cocok untuk eksplorasi/testing di jaringan terpercaya. Untuk produksi, gunakan Nginx + domain (Opsi B).

Opsi B — Domain + Nginx Reverse Proxy (recommended)

Konfigurasi Nginx untuk proxy request ke app Streamlit dengan WebSocket support + HTTPS.

nginx
location / {
    proxy_pass http://127.0.0.1:9120/;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_read_timeout 86400s;
    proxy_buffering off;
}

Untuk HTTPS, gunakan certbot --nginx dengan domain Anda.

Scraping Terjadwal

For trend monitoring, scheduled_scrape.py menjalankan scraping headless sesuai jadwal cron. Hasil disimpan ke hasil/scheduled_*.csv dan ditampilkan di card "Tren Historis" pada dashboard.

crontab
# Run every 6 hours
0 */6 * * * cd /opt/sentiment-analysis && ./venv/bin/python3 scheduled_scrape.py \
    --keyword "your-keyword" \
    --yt 60 --web 8 --ps 60 \
    >> /var/log/sentiment-analysis_cron.log 2>&1
Trend Tracking Dashboard membaca semua file scheduled_*.csv dan menampilkan GSS dari waktu ke waktu. Setelah 2+ scheduled run, chart "Tren Historis" muncul otomatis.

Security Notes

Perlakukan kredensial seperti password Facebook cookies dan TikTok ms_token memberikan akses penuh ke akun. Simpan dengan aman dan rotate secara berkala.

Penyimpanan Kredensial

Kredensial platform disimpan secara lokal di sessions/ sebagai file JSON. Tidak pernah meninggalkan server Anda.

LLM API Key

LLM API key dibaca dari environment variables atau .env. Never commit .env to git (it's in .gitignore).

Tidak Ada Persistensi Data

Data hasil scrape hanya ada di session browser saat ini. Refresh page akan menghapusnya. Scheduled scrape disimpan ke CSV untuk tracking tren.

Tidak Ada Sharing Data Eksternal

Komentar dikirim ke LLM API hanya untuk generate summary. Tidak ada analytics atau tracking pihak ketiga.

Rate Limiting

Perhatikan limit API platform. Gunakan nilai max yang wajar per sumber. Instagram sering butuh proxy.

Limitations

Limitasi API Platform

PlatformLimitasi
InstagramMungkin butuh proxy; sering kena rate-limit. Session kadaluarsa secara berkala.
YouTubeJumlah komentar dibatasi oleh youtube-comment-downloader. Diurutkan terbaru.
Web NewsTergantung Bing News RSS + parsing artikel trafilatura.
Play StoreTerbatas pada review yang tersedia via google-play-scraper. Diurutkan terbaru.
FacebookBerbasis cookie; bisa rusak saat Facebook mengubah struktur DOM.

Model Accuracy

IndoBERT mencapai akurasi ~85% untuk sentimen Bahasa Indonesia. Prediksi low-confidence (< 0.6) ditandai "ragu". Untuk bahasa lain, ganti SENTIMENT_MODEL di .env.

Limitasi Lain

  • No real-time monitoring — Ini adalah tool snapshot, bukan pipeline continuous.
  • Single-user — Tidak dirancang untuk concurrent user. Setiap session independent.
  • Trend visualization — Butuh data scrape punya timestamp valid. Tidak semua platform menyediakan timestamp yang reliable.
  • LLM dependency — AI insight butuh LLM API endpoint yang berfungsi.
